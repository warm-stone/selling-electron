# Windows 真机验证清单

> 本清单覆盖 CI 与单测无法自动化的真机环节（实机打印机、扫码枪、安装体验、手动备份）。
> 每项含**操作步骤 / 预期结果 / 勾选框**，逐项执行并勾选。
> 适用版本：v0.4.3；安装包来源：GitHub Releases（tag `v0.4.3` 自动构建发布，文件名 `selling-electron-setup-0.4.3.exe`）。

## 准备

- 一台 Windows 10/11 x64 电脑（管理员账户）
- 热敏小票打印机一台（USB 或网口，已通电）
- 扫码枪一支（HID 键盘模拟型，USB 即插即用）
- 从 CI 下载的安装包 `selling-electron-setup-0.4.3.exe`

## 1. 安装与首次启动（首启建库）

1. 双击 `selling-electron-setup-0.4.3.exe`

4. 打开资源管理器进入 `%APPDATA%\selling-electron\`（地址栏直接粘贴回车）

**预期结果**

- [ ] 安装向导全程中文，可更改安装目录
- [ ] 启动后出现应用主窗口（左侧菜单：收银台/商品管理/进货管理/销售记录/报表/模板编辑/设置）
- [ ] `%APPDATA%\selling-electron\pos.db` 文件存在（首启自动建库，含全部数据表）
- [ ] 再次双击启动不出现第二个窗口（单实例锁生效，已有窗口被聚焦）

### 云「外卖」打印机（得力 DL-5801PW 等）：spooler 打得出英文、中文/Logo 不出 → 切 driver 通道

> 背景（**20261118 F1 编码探针已定证**，原始记录见 §11.3 步骤 2 回填）：这类「云」打印机的
> 固件**没有中文字模**——RAW 通道对每个 ≥0x80 字节「吃掉 + 推进一个半角空位 + 不画点」，
> UTF-8 与 GBK+`FS &` 两种编码同样打不出中文；而 ESC/POS **指令层与 `GS v 0` 光栅层完好**
> （探针 S4 实心黑块正常出图）。所以「中文不出」既不是编码选错、也不是指令不被执行，而是
> 字形层缺失；同一台机器走 Windows 打印机驱动渲染（Word 打印的同一条路径）中文与图片都正常
> ——驱动替它光栅化了。应用已内置 **driver 驱动渲染通道**（收据渲染成 HTML → 系统驱动光栅化）
> 作为此类机型的兜底。
>
> 另一条同样可行的路线是「全页光栅化 → `GS v 0` → spooler RAW」（由应用自己光栅化，不依赖
> 驱动，可附切纸/浓度等 ESC/POS 指令，且与传输无关），**本轮暂不实施**——取舍与实施前必读的
> 两个约束见 §11.3 回填。

**操作步骤**

1. 设置页「打印通道」选择 `driver`（驱动渲染），「打印机」选择该云打印机
2. 点击「测试打印」
3. 重复第 4 项的结账 → 预览 → 打印全流程一次

**预期结果**

- [ ] 测试打印出纸：中文、Logo（已上传时）全部正常，版式与预览一致
- [ ] 结账小票实纸内容与预览一致（中文/对齐/倍高倍宽/粗体/Logo 逐项核对）
- [ ] driver 通道无自动切纸指令（驱动渲染页高按内容自适应；裁切位置以纸面剪切示意线为准）
- [ ] 打印速度略慢于指令直发属正常（驱动渲染整页位图）

## 11. v2 真机闭环（诊断复采 + driver 实验三组）

> 背景：printer-diagnostics v2 修复了首轮真机报告（20261115-170820）暴露的 3 个采集 bug
> （PrinterStatus 位掩码误读 / WER 遥测噪音冒充崩溃 / 视口地板值假溢出）与 3 个盲区
> （printConfig v4 驱动失明等），并为症状 2（driver 通道版面异常）提供两条实验性
> workaround 开关（设置页「打印高级选项（实验）」折叠区）。本节在**目标机**
> （DL-5801PW，Windows，DPR 1.25）上验证修复语义并做 spike C 三组对照实验。

### 11.1 诊断复采（修复语义验证）

**操作步骤**：安装 v2 构建 → 设置页「打印机诊断」→ 开始诊断 → 导出报告

**预期结果**（对照首轮报告 20261115-170820 逐项翻转）

- [ ] 打印机列表 4 台全部显示「在线」（首轮全 unknown——位掩码 0=Normal 修复）
- [ ] 报告摘要行「WER 崩溃（Application Error 1000）0 条」（首轮 18 条全是
      UndockedHost 遥测噪音——ProviderName 过滤修复）
- [ ] renderSnapshot 无水平溢出（首轮 scrollWidth=786 假阳性——元素级测量修复后
      应为收据实宽 ≈221px）
- [ ] 「发现问题」区恰好两条新 finding：
      ① [高] driver-print-combo-known-issue（R16：driver+自定义页宽+零边距坏组合，
      含 203 dpi / 驱动默认页尺寸 / 切回 spooler 三条 workaround 文案）；
      ② [信息] printconfig-unavailable（R17：v4 驱动 DEVMODE 配置不可读，
      页宽比对类诊断本轮不可用）
- [ ] 报告 printConfig 段：记录该机 fallback 链命中层（source=printconfiguration /
      printticketxml / win32printerconfig / devmode 之一，或链终值仍空）——回填
      开发侧 fixture real-machine-20261115.json 的 source 键

> **回填（2026-11-17，报告 131844 / 132143）**：上述预期三项有两项被真机证伪，
> 已据此改代码（v3）：
>
> - **renderSnapshot 仍有溢出，且是真溢出不是假阳性**：`scrollWidth=237 > paperWidthPx=221`
>   （两份报告完全一致，dpr=1.25）。原因不是测量 bug，是版面 bug——32 列按「半角推进
>   = 0.5em」排布，而目标机中文字体回退后半角推进实测 0.594em，237/221 = 1.072 正好对得上。
>   v3 修复：版面宽度锚定到 mm（58mm 纸 → 可打印宽 48mm = 181px）+ 渲染前按
>   `scrollWidth/clientWidth` 比例回缩字号（`FIT_TO_WIDTH_BODY`，≤8 轮），并新增
>   `fontProbe`（digitPx/spacePx/cjkPx/fontSizePx/availableFonts）把字体度量写进报告取证。
> - **R17 未命中**：该机 printConfig 可读，DL-5801PW = `widthMicrons 48000 × heightMicrons 297000`、
>   `paperSize` 名为空、`source='win32printerconfig'`（fixture 的 source 键据此回填）。
>   **页高 297mm 是 A4 残留高度**——驱动默认页尺寸实为「48mm 宽 × A4 高」。
> - **命中的是 R10 driver-page-size-ignored + R11 printable-area-clip**，且是**基准假阳性**：
>   两条规则拿模板纸宽 58000μm 当基准去比 48000μm，但 48mm 是 58mm 纸的正常可打印宽度
